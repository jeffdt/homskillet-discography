     Implementation Plan: Fullscreen Resizing and 90-Degree Rotation

     Overview

     Fix visualizer fullscreen mode so both analyzer and spectrogram resize 
     properly, and add 90-degree rotation option for widescreen displays.

     User's Key Insight

     Instead of maintaining two rendering code paths (vertical vs horizontal
      scrolling), we can:
     1. Keep all existing rendering logic (vertical mode)
     2. Simply rotate the canvas visually using CSS transform: rotate(90deg)
      as a final display step

     This dramatically simplifies the implementation!

     Rotation Strategy Comparison

     Option A: CSS Transform Rotation (RECOMMENDED - Simpler)

     How it works:
     - Canvas renders normally (vertical mode, existing logic)
     - Apply transform: rotate(90deg) to canvas elements when in rotation 
     mode
     - Adjust container layout to accommodate rotated dimensions
     - Zero changes to Spectrogram.js rendering logic!

     Pros:
     - Single rendering code path (existing vertical logic)
     - Minimal code changes (mostly CSS and layout)
     - No performance overhead from dual rendering modes
     - Maintains all existing visualization logic intact

     Cons:
     - CSS rotation may cause slight anti-aliasing blur on some browsers
     - Container sizing needs careful handling (rotated 448x800 becomes 
     800x448 visually)
     - May need transform-origin adjustments for proper positioning

     Implementation:
     .Visualizer.rotated .Visualizer-analyzer,
     .Visualizer.rotated .Visualizer-spectrogram {
       transform: rotate(90deg);
       transform-origin: center center;
     }

     .Visualizer.rotated {
       /* Adjust container to accommodate rotated dimensions */
     }

     Option B: Dual Rendering Modes (Original Plan - More Complex)

     How it works:
     - Separate rendering logic for vertical and horizontal scrolling
     - Rewrite scrolling in updateFrame() to handle both orientations
     - Swap drawing axes based on mode

     Pros:
     - Perfect pixel-level control
     - Maximum flexibility for future enhancements

     Cons:
     - Significant code duplication in Spectrogram.js
     - Two code paths to maintain and test
     - Higher complexity and bug surface area
